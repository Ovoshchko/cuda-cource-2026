# Lab 1: Vector Operations and Activations — Векторные операции и активации

## Описание

`submission` выполняет Add (`x + y`), SAXPY (`alpha * x + y`) и ReLU (`max(0, x)`) над векторами `float`. Каждая операция поддерживает коалесцированный и некоалесцированный доступ к глобальной памяти. Для проверки используется эталон на основе `std::transform` и арифметических операций стандартной библиотеки C++.

## Окружение

Замеры получены на одном GPU NVIDIA Quadro RTX 6000 с 24 GiB памяти и compute capability `7.5`.

- Драйвер NVIDIA `590.48.01`, CUDA Toolkit `13.1`, NVCC `13.1.115`.
- Ubuntu `24.04.5 LTS`, ядро Linux `5.15.0-204-generic`.
- GCC `13.3.0`, CMake `3.28.3`, `libstdc++6` `14.2.0-4ubuntu2~24.04.1`.
- Сборка `Release`, C++17, `-O3`, `-DNDEBUG`, целевая архитектура `sm_75`.

## Компиляция

Команды сборки выполняются из каталога лабораторной. Значение `75` задаёт архитектуру Quadro RTX 6000. CMake включает CUDA Runtime, эталон использует стандартную библиотеку C++.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=75
cmake --build build --target submission benchmark
```

## Запуск

```bash
./build/submission --help
./build/submission --input examples/input_10.txt --output build/coalesced.txt
./build/submission --input examples/input_10.txt --output build/noncoalesced.txt --mode noncoalesced
```

`--input` и `--output` задают пути к входному и выходному файлам. Вход начинается с `N alpha`, после которых идут ровно `N` пар `x y`. Числа разделены пробельными символами, дробная часть записывается через точку. `alpha`, `x` и `y` считываются как `float`.

Для каждой входной пары записывается строка с тремя числами через пробел в порядке Add, SAXPY, ReLU. Выход содержит только эти строки. Значения записываются с точностью до девяти значащих цифр.

`--mode` выбирает `coalesced` (по умолчанию) или `noncoalesced`. Отдельный запуск с `--help` печатает справку. Пустой или некорректный вход, `N = 0` и неверные аргументы дают код `2`. Ошибка вычисления или записи результата даёт код `1`. Сообщения об ошибках выводятся в `stderr`.

## Реализация

Для `n` элементов `submission` запускает `ceil(n / 256)` блоков по 256 потоков. Каждое ядро вычисляет индекс `i` по одной из двух формул. Потоки с `i >= n` завершаются до обращения к массивам. [kernels.cu](src/kernels.cu)

| Режим | Индекс `i` | Шаг между соседними потоками блока |
| --- | --- | ---: |
| `coalesced` | `blockIdx.x * blockDim.x + threadIdx.x` | 1 элемент |
| `noncoalesced` | `threadIdx.x * gridDim.x + blockIdx.x` | `gridDim.x` элементов |

Выбор режима меняет формулу индексации при одинаковой сетке. При одном блоке формулы совпадают. В `run_operations()` четыре GPU-буфера выделяются через `cudaMalloc`. `cudaMemcpy` переносит входы `x` и `y` на GPU, а затем возвращает три результата на CPU. Add запускается до SAXPY, который обновляет `y` на месте. `CUDA_CHECK` проверяет статусы выделения, копирования и запуска, а `std::unique_ptr` освобождает буферы через `cudaFree`. [main.cu](src/main.cu) · [cuda_check.h](include/cuda_check.h)

## Проверка корректности

`benchmark --check` вычисляет эталон на CPU через `std::transform` из стандартной библиотеки C++. Входы `float` генерируются через `std::mt19937` с seed `2026` и распределением на интервале `[-1, 1]`. В первый элемент обоих векторов записывается ноль. Если длина позволяет, следующие две пары задают явно, чтобы проверить оба знака. Для SAXPY GPU-ядро и эталон получают один и тот же исходный `y` и коэффициент `2`.

Использовались блоки по 256 потоков и размеры `1`, `255`, `256`, `257`. Последний размер проверяет неполный второй блок. Допуск абсолютной ошибки равен `1e-5`. Все 24 проверки завершились с `PASS`. Таблица показывает максимальную ошибку и число несовпадений по четырём размерам для каждой пары операции и режима. При отклонении выше допуска проверка возвращает код `1`.

| Операция | Режим | Операция эталона | Размеры | Максимальная ошибка | Несовпадения | Результат |
| --- | --- | --- | --- | ---: | ---: | --- |
| Add | coalesced | `std::plus<float>` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |
| Add | noncoalesced | `std::plus<float>` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |
| SAXPY | coalesced | `std::fma` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |
| SAXPY | noncoalesced | `std::fma` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |
| ReLU | coalesced | `std::fmax` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |
| ReLU | noncoalesced | `std::fmax` | 1, 255, 256, 257 | 0.000e+00 | 0 | PASS |

На готовых входах из `examples/` с 2, 10 и 100 000 элементами выходные файлы двух режимов совпали побайтно. В каждом файле число строк результатов совпало с размером входа.

Пример из задания с `N = 3` и `alpha = 0.5` дал ожидаемый файл в обоих режимах. Отдельно проверены `--help` с кодом `0`, неверные аргументы и входы с кодом `2`, а также ошибка открытия выходного файла с кодом `1`.

## Результаты

Для каждой операции, длины вектора и размера блока оба режима получают одинаковые данные и одинаковое число потоков. Измерялись блоки из 128, 256 и 512 потоков. Копирования используют закреплённые буферы CPU и `cudaMemcpyAsync` в потоке CUDA по умолчанию. Перед каждым запуском SAXPY исходный `y` снова копируется на GPU.

Четыре CUDA Events отмечают начало цикла и конец каждого из этапов H2D, ядра и D2H. Перед чтением интервалов бенчмарк ждёт последнее событие через `cudaEventSynchronize`. После двух прогревов для каждого интервала и полного цикла отдельно берётся медиана девяти повторов. Выделение памяти измерено отдельно и исключено из полного цикла.

```bash
./build/benchmark 1000000 10000000
./build/benchmark --mode noncoalesced 10000000
```

## Выводы

- На 10 000 000 элементов с блоком из 256 потоков коалесцированный режим ускорил ядра Add, SAXPY и ReLU в 3,14, 3,35 и 3,24 раза соответственно. Например, Add занял 0,214 мс в `coalesced` и 0,671 мс в `noncoalesced`.
- Время полного цикла уменьшилось примерно на 3,4–4,7% при той же конфигурации. Для `coalesced` Add копирования заняли около 10,5 мс при полном времени 10,736 мс. ReLU копирует на GPU один входной вектор, поэтому её H2D занимает примерно вдвое меньше времени, чем H2D для Add и SAXPY.
- На 10 000 000 элементов время `coalesced` Add менялось от 0,213 до 0,215 мс при смене размера блока. В `noncoalesced` Add переход с 128 на 512 потоков уменьшил время ядра с 0,902 до 0,605 мс. В этой реализации размер блока меняет число блоков, а с ним и шаг адресов в `noncoalesced`.
- При увеличении входа с 1 до 10 млн элементов время ядра `coalesced` Add при 256 потоках выросло с 0,025 до 0,214 мс, а полный цикл — с 1,085 до 10,736 мс. Эти замеры относятся к одному GPU и закреплённой памяти CPU. Полный цикл охватывает переносы и вычисление. Чтение и запись текстовых файлов выполняются отдельно в `submission`.

## Воспроизводимость

### Данные

Готовые входы для `submission` лежат в `examples/`. Коэффициент SAXPY в этих файлах равен `2`.

- [input_2.txt](examples/input_2.txt) на 2 элемента в каждом векторе.
- [input_10.txt](examples/input_10.txt) на 10 элементов, включая нули, положительные и отрицательные дробные числа.
- [input_100000.txt](examples/input_100000.txt) на 100 000 элементов с детерминированными целочисленными значениями.

Бенчмарк генерирует свои векторы с seed `2026` на интервале `[-1, 1]` и явно добавляет нули, положительные и отрицательные значения. Позиционные аргументы задают размеры массивов. Для отчёта использованы 1 и 10 млн элементов и коэффициент SAXPY `alpha = 2`. Размер по умолчанию без аргументов равен `4194304`.

### Полный запуск

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=75
cmake --build build --target submission benchmark
for n in 2 10 100000; do
  ./build/submission --input "examples/input_$n.txt" --output "build/coalesced_$n.txt"
  ./build/submission --input "examples/input_$n.txt" --output "build/noncoalesced_$n.txt" --mode noncoalesced
  cmp "build/coalesced_$n.txt" "build/noncoalesced_$n.txt"
done
./build/benchmark --check
./build/benchmark 1000000 10000000
```
